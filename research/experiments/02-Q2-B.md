## 1. Setup
- **Question (Q2):** how high will US influenza-like-illness activity (weighted ILI %) be in 2 and 4 weeks; plus an h=0 nowcast of the not-yet-published week.
- **Truth:** Delphi Epidata FluView `wili`, region `nat`, epiweek 201040 → 202636: 831 weekly values (2010-10-09 → 2026-09-05, Saturday week-ends), **no missing weeks, no NaNs**. Cached `data/truth/fluview_wili_nat.csv`.
- **Queries:** seeds `flu, flu symptoms, influenza, fever` → `gt.expand_queries(..., geo="US", timeframe="today 5-y", max_per_seed=12)` → 44 terms. Dropped 6 as clearly unrelated to ILI: `indiana fever` (WNBA), `fever game`, `night fever`, `fever up` (songs), `yellow fever` (travel vaccine), `baby fever` (idiom). **38 terms kept**, pulled individually (weekly, `today 5-y`, 261 rows 2021-09-12 → 2026-09-06). Zero-share filter dropped none (max zero share 0.000). Kept but flagged as news-driven rather than symptom-driven: `bird flu`, `covid`, `virus`.
- **Alignment:** `truth.align(y, X, "W")` on Saturday-ending periods → **260 common weeks, 2021-09-18 → 2026-09-05, 0 period gaps, 0 NaN cells** (no gap handling was needed). One GT week (ending 2026-09-12) extends beyond the last published ILI week → used as the nowcast origin.
- **Information set:** FluView publishes with a one-week lag, so all horizons use `y_known_at_origin=False`: at origin t the model sees GT through week t and ILI through t−1. The naive benchmark is therefore the **last known value y_{t−1}** (implemented as `ev.naive(h+1)` for h≥1, `ev.naive(0)` for h=0). AR benchmark uses the same lag structure.
- **Horizons:** h=0 (nowcast), h=2, h=4 weeks ahead of the origin (3 and 5 weeks ahead of the last known ILI).
- **Preprocessing:** `pp.raw_pipeline` (ZeroRepair → log(x+1)), fitted inside each training window. Levels, no transform.
- **Models:** ARX `lasso` and `enet` (LassoCV / ElasticNetCV with time-series inner CV, standardised in-window), AR lags p=8, xlags=1, Fourier period 52 k=2, min_train=104; (a) expanding window `*_exp`, (b) ARGO sliding `window=104` `*_w104`. ARGO's p=52 tried for lasso (`lasso_p52_*`) — it ran, but with only 260 aligned rows it leaves ~50 training rows for 132 columns.
- **Benchmarks:** naive (last known), seasonal_naive(52), ar (p=8 + Fourier). `bench=` the best target-only model by full-sample RMSE per horizon: **ar** for h=0 and h=2, **seasonal_naive** for h=4.
- **Evaluation window:** origins start 104 weeks after 2021-09-18, i.e. the targets run **2023-09 → 2026-09** (n = 156 / 153 / 151), covering the 2023-24, 2024-25 (severe) and 2025-26 seasons.

## 3. Verdict
| horizon | `ev.verdict` (full sample = excluded window) |
|---|---|
| h=0 | gt_helps=**True**, strength=**strong**, best=lasso_w104, OOS R²=0.50 vs ar, CW p=0.001, DM p=0.049 |
| h=2 | gt_helps=True, strength=moderate, best=enet_w104, OOS R²=0.16 vs ar, CW p=0.000, DM p=0.45 |
| h=4 | gt_helps=True, strength=moderate, best=enet_w104, OOS R²=0.15 vs seasonal_naive, CW p=0.007, DM p=0.60 |

Honest reading, per horizon:
- **h=0:** real and robust — every p=8 GT configuration cuts RMSE by ~30 % and squared error by ~50 % vs AR(8)+Fourier, with both CW and DM significant; window choice hardly matters. This is the ARGO result reproduced on 2023-26 data, with the unpublished-week problem framed correctly (ILI for the current week is unknown, GT for it is known).
- **h=2:** fragile — the RMSE gain (OOS R² 0.09–0.16) comes from peak weeks, while MAE and MAPE are *worse* than AR (25–31 % vs 19.6 % MAPE): GT models over-react in the low off-season. DM is far from significant; only Clark–West (which credits any signal in the nested model) supports it.
- **h=4:** not reliable — five of six GT configurations lose to seasonal-naive on RMSE and all lose on MAE/MAPE; only `enet_w104` has positive OOS R² (0.15) with DM p=0.60. The library verdict says "moderate" because the rule is OOS R² > 0.02 and CW < 0.10, but one configuration out of six is selection, not evidence. Seasonal-naive is the honest answer at 4 weeks.
- ARGO's p=52 is dominated by p=8 at every horizon: 260 aligned weekly rows are too few for 52 AR lags plus 76 GT columns.

## 5. Surprises / problems
1. **Leakage bug found and fixed mid-experiment (library, not this cell).** `ev.rolling_backtest` with `y_known_at_origin=False` trained on rows whose target date equalled the origin — for h=0 that is the very value being nowcast. The fix (training rows must have target date ≤ y_{t−1}) landed in `evaluate.py` while my first run was executing; that run was killed and everything here comes from the rerun on the fixed code. Nowcast gains reported before the fix would have been inflated.
2. **`ev.forecast_next` had no publication-lag origin for h≥1.** With `y_known_at_origin=False` it set the origin to the last *known* ILI week, discarding the newest GT week and mismatching the backtest. Extended (minimal edit in `evaluate.py`): when `y_known_at_origin=False` and X extends beyond y, the origin is the first GT period without ILI, exactly as in the h=0 branch. `forecast_next` h≥1 with `y_known_at_origin=True` is unchanged.
3. **The mandated exclusion window is a no-op** for weekly GT (5-year window) — see §2. Any flu cell using `today 5-y` will have this property; the skill should detect an exclusion window that removes zero targets and say so.
4. **Naive must be defined on the real information set.** `ev.naive(h)` for h≥1 uses y_t, which is not published at the origin; I used y_{t−1}. Without this, the naive benchmark is silently one week stronger than anything it is compared with.
5. **RMSE vs MAE disagreement at h=2/h=4** — GT models win on RMSE (peaks) and lose on MAE/MAPE (off-season); a verdict based on squared error alone overstates the gain for a series whose level varies 10× across the year.
6. **LASSO is not sparse here** (40–55 active columns) — the CV-chosen penalty is small, so "which queries" is not a stable story; the query-frequency table in the JSON is more reliable than a single origin's list.
7. Runtime: 1454 s total (h=0 160 s, h=2 501 s, h=4 791 s) with 2 sibling cells competing for CPU; ElasticNetCV (4 l1 ratios × 30 alphas) is the slow part.
8. `pd.DataFrame.to_markdown` needs `tabulate`, which is not installed — tables were rendered by hand.

## 7. Recommendation for the skill
For weekly epidemiological questions like Q2 the skill should default to the ARGO-style setup used here (individual weekly pulls of an expanded query set, log-raw preprocessing, LASSO/ENet ARX with p≈8, 1 GT lag and Fourier terms, expanding or 104-week window — both work) **and frame the answer as a nowcast plus short-range extrapolation**: at h=0 GT reliably halves the AR error and the skill can state the unpublished week with a tight interval; at 2 weeks it should present the GT forecast alongside the AR forecast and say the gain is limited to peak weeks; at 4 weeks it should refuse to claim GT value and report the seasonal-naive/AR forecast with a wide interval. It must (i) build benchmarks on the actual information set (last *published* value), (ii) select the benchmark as the best of naive/seasonal-naive/AR per horizon, (iii) report MAE/MAPE next to RMSE and require agreement before saying "GT helps", (iv) notice when the exclusion window removes no targets, (v) flag news-driven terms (`bird flu`, `covid`) among the drivers, and (vi) not attempt ARGO's 52 AR lags with a 5-year weekly sample.
