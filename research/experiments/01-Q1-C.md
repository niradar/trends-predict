## 1. Setup
- **Question (Q1):** What will the US unemployment rate be next month?
- **Truth:** BLS `LNS14000000` (`truth.bls_series("UNRATE")`), monthly SA, 2004-01 → 2026-08 (271 obs). Last print 4.1 % (Aug 2026).
- **Queries (14, individual monthly pulls, `geo=US`, `2004-01-01 → today`):** the 10 smoke-test terms
  (unemployment, unemployment benefits, file for unemployment, unemployment office, jobs hiring, indeed jobs,
  layoffs, severance, job openings, resume) + 4 chosen from `gt.related_queries` on seeds "unemployment" and
  "layoffs" (top related, excluding state- and company-specific terms): **unemployment claim, unemployment login,
  unemployment insurance, tech layoffs**. 0 dropped by the privacy-zero filter. Aligned with `truth.align(y, X, "M")`.
- **Horizons:** h=0 nowcast (`y_known_at_origin=False`: latest month's rate unknown, its GT known) and h=1.
- **Window:** expanding, `min_train=60`, last 120 origins (targets 2016-09 → 2026-08). `transform="diff"` for all
  direct models; p=3 AR lags, GT lags 0–1, period 12, 1 Fourier pair.
- **Preprocessing ablation (fitted inside each training window):**
  raw = `ZeroRepair → log1p`; djorno = `ZeroRepair → log1p → EWMA(halflife=1) → rolling detrend(12) → cluster(0.4)`;
  variants `halflife=0` (no smoothing) and `cluster=False` (standardise instead of cluster).
- **Models:** (1) no GT: naive, seasonal_naive, ar_diff, SARIMAX(1,1,0); (2) ridge + raw GT; (3) ridge + djorno
  {default, hl0, nocluster}; (4) SARIMAX(1,1,0) with djorno-preprocessed GT exog.
- **Benchmark:** best target-only model by full-sample RMSE = **naive** at both horizons (naive 1.02 vs
  SARIMAX 2.06 vs ar_diff 2.20 vs seasonal naive 2.37).
- **Cluster membership (djorno pipeline fitted on the full aligned sample):**
  - `cluster4[unemployment+6]`: unemployment, unemployment benefits, file for unemployment, unemployment office,
    unemployment claim, unemployment login, unemployment insurance
  - `cluster5[layoffs+1]`: layoffs, tech layoffs
  - `cluster1[job openings+1]`: job openings, resume
  - singletons: jobs hiring, indeed jobs, severance
  → 14 queries collapse to 6 features (one big "claims/benefits" factor, one "layoffs" factor, one "job search" factor).

Honest reading: with 14 keywords and ridge, Djorno-style preprocessing (detrend, no clustering) beats the random
walk by ~21 % MSE in calm months at h=0 with a significant Clark–West test but a non-significant DM (p=0.18);
it does *not* survive the pandemic months (full-sample OOS R² −0.66), and no GT configuration beats naive at h=1
except raw GT in the excluded view, which is not robust across the ablation (the three djorno variants are all
negative there) and so should be treated as noise-level evidence.

## 4. Forward forecast
- **Configuration used:** `ridge + djorno(period=12, halflife=1, detrend="rolling", cluster=False)`, xlags=1, p=3,
  Fourier k=1, `transform="diff"` (best h=0 shock-excluded OOS R²).
- **h=0 nowcast was not possible:** `gt.fetch_interest` drops the `isPartial` current month (Sept 2026), so GT ends
  2026-08 — the same month as the last BLS print — and `ev.forecast_next(h=0)` correctly fell back to h=1 (note
  field `"no unpublished period to nowcast; returned h=1 forecast"`). The forecast below is therefore an **h=1
  forecast from origin 2026-08** for the **September 2026** rate (BLS release early October 2026).
- **Point: 4.06 %**, 90 % conformal interval (last 36 backtest residuals, half-width 0.23): **[3.83, 4.28]**.
- **Reference:** naive 4.1 % [3.9, 4.3]; ar_diff 4.01 % [3.75, 4.27]. The GT model's answer is a −0.04 pp change,
  i.e. statistically "unchanged at 4.1 %, if anything a tick lower".
- **Drivers (ridge coefficients, standardised, on the monthly change):** `file for unemployment` (l1 −0.024,
  l0 +0.024), `unemployment login` (l1 −0.021), `unemployment office` (l0 +0.021), `unemployment insurance`
  (l1 −0.019, l0 +0.018), `y_lag1` (−0.018), `unemployment` (l1 −0.016). The sign pattern (l0 positive, l1 negative)
  means the model reacts to the *month-on-month rise* in claims-related search; all coefficients are tiny, so the
  forecast is dominated by the random-walk base.

## 5. Surprises / problems
1. **Clustering hurt.** The Djorno default merged 7 claims/benefits terms into one factor; the un-clustered
   variant was best (R² 0.22 vs 0.09 at h=0 excl.). At 14 well-chosen terms there is little redundancy to remove
   and ridge already handles collinearity; clustering should be optional, not default, for small keyword sets.
2. **SARIMAX(1,1,0) + GT exog is the worst GT model** (RMSE 0.25 vs naive 0.14 in calm months) and its CW p is
   still 0.02 — another reminder that Clark–West alone is not evidence of a usable forecast.
3. **AR-diff overshoot in 2020:** after the +10.3 pp April 2020 jump the AR(3)-in-differences model predicted
   34.1 % for May (true 13.2), RMSE 2.20 on the full sample. The smoke test reported 0.84 for the same model;
   `src/trends_predict/evaluate.py` was modified between the smoke run and this cell (19:40 → 19:46 → 19:51),
   so the two numbers are from different library versions. Shock-excluded numbers match (0.162 vs 0.159).
4. **Library edited while the cell ran:** `ev.verdict` gained a stricter "strong" rule (now needs DM p < 0.10)
   between my first and second run — the h=0 excl. verdict moved from "strong" to "moderate" with identical
   numbers. The JSON reflects the current rule.
5. **Shared GT catalog:** other cells (elections, Hebrew keywords) ran concurrently, so `len(gt.catalog())`
   before/after over-counted (12 → 165). Requests are counted by matching single-keyword vintages instead.
   "unemployment claim" got two vintages one minute apart (429 retry or concurrent cell) — counted against me.
6. **Rate limiting:** three `429` warnings during the 5 pulls; back-off succeeded, no `TrendsUnavailable`.
7. No leakage found: pipelines are fitted per origin on `X[:t]`, the design uses target date ≤ origin, and the
   GT-in-2020 nowcast *lost* to naive here (unlike the smoke test's lasso), which is consistent with an honest setup.

## 7. Recommendation for the skill
For persistent monthly macro series like UNRATE the skill should (a) model changes (`transform="diff"`) and
benchmark against the random walk, (b) treat Djorno preprocessing as **detrend first, cluster optionally** — run
the `cluster=False` variant alongside the default and pick by shock-excluded OOS R², (c) frame any GT claim as a
**nowcast of the not-yet-published month** and report both the full-sample and shock-excluded verdicts side by
side, and (d) refuse to claim a GT gain for h ≥ 1 at monthly frequency: no configuration beat naive there, and the
single positive cell (raw GT, h=1 excl.) is not robust across the ablation. It should also warn when the current
month is only partially observed in GT (as now), so the "nowcast" is really an h=1 forecast, and should never
report SARIMAX-with-exog as a GT model without checking it against naive — here it lost by a factor of ~3 in RMSE
while passing Clark–West.
